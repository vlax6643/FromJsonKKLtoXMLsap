# Сопоставление полей ККЛ JSON → IDoc WPUBON01 XML

Пример на основе файла `KKL_20260508133041.json` → `WPUBON01_0000000004_20260508_4567_0000002.xml`.

---

## Шапка ккл (один раз на файл)

| JSON поле | JSON значение | XML элемент | XML значение | Преобразование |
|---|---|---|---|---|
| `dpt` | `"00004"` | `EDI_DC40/SNDPRN` | `0000000004` | zfill(10) — дополнение нулями слева до 10 символов |
| `register` | `"4567"` | `E1WPB01/KASSID` | `4567` | без изменений |
| `cashier` | `"Администратор"` | `E1WPB01/KASSIERER` | `Администратор` | без изменений |
| `cashier` | `"Администратор"` | `E1WPB01/CSHNAME` | `Администратор` | без изменений (ФИО = имя пользователя кассы) |
| `code` | `"0000002"` | — | — | в имя файла и журнал, в XML не идёт |
| `full` | `"1"` | — | — | только в журнал |
| `shift` | `"347"` | — | — | не используется |

---

## На каждый чек — один блок `<IDOC>`

Чеки группируются по полю `receipt` из `lines[]` и `payments[]`.
Пример содержит два чека: `receipt=17` и `receipt=18`.

---

## Имя выходного файла

```
WPUBON01_{SNDPRN}_{VORGDATUM}_{register}_{code}.xml
```

Пример: `WPUBON01_0000000004_20260508_4567_0000002.xml`

| Часть имени | Источник | Значение |
|---|---|---|
| `0000000004` | `dpt` zfill(10) | номер магазина |
| `20260508` | `date` шапки ккл | дата ккл |
| `4567` | `register` | номер кассы |
| `0000002` | `code` | номер ккл |

## Карты лояльности `cards[]`

Пример (из `KKL_20260508150516.json`, чек №20):

```json
"cards": [
  {
    "receipt": 20,
    "date": "2026-05-08 15:01:50",
    "card": "0001",
    "card_type": "0000001",
    "nominal": null,
    "sum": 449.96
  }
]
```

| JSON поле | JSON значение | XML элемент | XML значение | Примечание |
|---|---|---|---|---|
| `cards[0].card` | `"0001"` | `E1WPB01/ZNOCARD` | `0001` | номер карты лояльности |
| `cards[0].card_type` | `"0000001"` | — | — | тип карты по справочнику Домино, в XML не идёт |
| `cards[0].receipt` | `20` | — | — | используется для привязки карты к чеку |
| `cards[0].nominal` | `null` | — | — | не используется |
| `cards[0].sum` | `449.96` | — | — | не используется |
| `cards[0].date` | `"2026-05-08..."` | — | — | не используется |

**Логика:** берётся первая карта из `cards[]` данного чека, её `card` идёт в `ZNOCARD`. Если `cards[]` отсутствует или пуст — `ZNOCARD` пустой тег.

Банковских карт в `cards[]` нет — `KARTENNR` в E1WPB06 всегда пустой.

## Поля JSON, которые НЕ попадают в XML

| JSON поле | Куда идёт |
|---|---|
| `code` | Имя файла, журнал |
| `full` | Журнал (`0`=промежуточная, `1`=итоговая) |
| `shift` | Не используется |
| `lines[].price` | Не используется (используется `sale`) |
| `payments[].date` | Не используется |
| `cards[].card_type` | Не используется |
| `cards[].nominal` | Не используется |
| `cards[].sum` | Не используется |
| `cards[].date` | Не используется |
