# Конвертер ККЛ JSON Домино → IDoc WPUBON01 SAP

Читает файлы ККЛ (Контрольно-Кассовая Лента) из кассовой системы Домино в формате JSON,
преобразует в XML IDoc формата WPUBON01 для загрузки в SAP IS-Retail.

---

## Что передаётся заказчику

Два файла:

| Файл | Назначение |
|---|---|
| `json_to_sap.exe` | Конвертер. Python на сервере не требуется — всё включено в exe |
| `json_to_sap.ini` | Конфигурация: пути к папкам, параметры SAP |

---

## Установка на сервер

### 1. Скопировать файлы

Создать на сервере рабочую папку, например `C:\KKL-SAP\`, и скопировать туда оба файла:

```
C:\KKL-SAP\
  json_to_sap.exe
  json_to_sap.ini
```

### 2. Настроить конфиг

Открыть `json_to_sap.ini` в Блокноте и задать пути и параметры SAP:

```ini
[paths]
inbox          = C:\KKL-SAP\inbox
outbox         = C:\KKL-SAP\outbox
processed      = C:\KKL-SAP\processed
journal        = C:\KKL-SAP\journal.db
log            = C:\KKL-SAP\logs\json_to_sap.log
retention_days = 30

[sap]
sndpor = SAPVOG
rcvpor = SAPVOG
rcvprn = SAP
```

> Параметры `sndpor`, `rcvpor`, `rcvprn` согласовываются с SAP-командой.

### 3. Первый запуск — проверка

Открыть командную строку (`cmd`), перейти в рабочую папку и запустить:

```
cd C:\KKL-SAP
json_to_sap.exe
```

При первом запуске автоматически создадутся папки `inbox\`, `outbox\`, `processed\`, `logs\`.
В консоли должно появиться:

```
2026-03-24 01:30:05 [INFO] === Конвертер ККЛ JSON -> IDoc WPUBON01 SAP запущен ===
2026-03-24 01:30:05 [INFO] Нет новых файлов в inbox.
2026-03-24 01:30:05 [INFO] === Готово ===
```

### 4. Тестовый прогон с файлом

Положить тестовый JSON в `inbox\` и снова запустить `json_to_sap.exe`.
Убедиться что в `outbox\` появился XML-файл и в логе статус `OK`.

### 5. Настроить Планировщик задач Windows

1. Открыть **Пуск → Панель управления → Администрирование → Планировщик задач**
2. Нажать **Создать простую задачу**
3. Заполнить:
   - **Имя:** `KKL-SAP Converter`
   - **Описание:** `Конвертер ККЛ Домино -> IDoc WPUBON01 SAP`
   - **Триггер:** По расписанию → Ежедневно, повторять каждые **15 минут**
   - **Действие:** Запуск программы
     - **Программа:** `C:\KKL-SAP\json_to_sap.exe`
     - **Рабочая папка:** `C:\KKL-SAP`
4. В свойствах задачи → вкладка **Общие**:
   - Установить: **Выполнять для всех пользователей**
   - Установить флаг: **Выполнять с наивысшими правами**
5. Сохранить и запустить задачу вручную, проверить что выполнилась без ошибок

> Рекомендуемый интервал — **каждые 15 минут**, как указано в ТЗ.

## Настройка (json_to_sap.ini)

### Секция `[paths]`

| Параметр | Описание | По умолчанию |
|---|---|---|
| `inbox` | Папка входящих ККЛ JSON файлов от Домино | `inbox\` рядом с exe |
| `outbox` | Папка исходящих WPUBON01 XML файлов для SAP | `outbox\` рядом с exe |
| `processed` | Папка обработанных входящих файлов | `processed\` рядом с exe |
| `journal` | Путь к файлу журнала SQLite | `journal.db` рядом с exe |
| `log` | Путь к лог-файлу | `logs\json_to_sap.log` рядом с exe |
| `retention_days` | Автоудаление файлов из `processed\` старше N дней. `0` — не удалять | `0` |

Пути можно указывать как абсолютные (`C:\KKL-SAP\inbox`) так и относительные от папки exe (`inbox`).

### Секция `[sap]`

| Параметр | Описание | Значение |
|---|---|---|
| `sndpor` | Порт отправителя (SNDPOR в EDI_DC40) | `SAPVOG` |
| `rcvpor` | Порт получателя (RCVPOR в EDI_DC40) | `SAPVOG` |
| `rcvprn` | Номер партнёра-получателя (RCVPRN в EDI_DC40) | `SAP` |

> Значения `sndpor`, `rcvpor`, `rcvprn` согласовываются с SAP-командой. Текущие значения подтверждены для магазина 7708.

### Автоочистка папки processed\

Параметр `retention_days` управляет автоматическим удалением старых файлов из `processed\`:

- `retention_days = 30` — удалять файлы старше 30 дней
- `retention_days = 0` — не удалять ничего (хранить вечно)

> Удаление файлов из `processed\` **не влияет на защиту от дублей** — она работает через журнал `journal.db`, а не через наличие файла на диске.

## Как это работает

1. Домино формирует ККЛ и кладёт JSON файл в папку `inbox\`
2. Планировщик запускает `json_to_sap.exe`
3. Конвертер находит все `.json` файлы в `inbox\`
4. Для каждого файла:
   - Проверяет журнал — не обрабатывался ли раньше (защита от дублей)
   - Парсит JSON, проверяет наличие обязательных полей
   - Группирует строки `lines[]` и `payments[]` по номеру чека (`receipt`)
   - Строит один `<IDOC>` на весь файл: `EDI_DC40` + по одному `E1WPB01` на каждый чек
   - Внутри каждого чека: `E1WPB02`+`E1WPB03`+`E1WPB04` на позицию, `E1WPB06` на оплату
   - Записывает XML файл в `outbox\`
   - Перемещает JSON в `processed\`
   - Записывает результат в журнал
5. SAP-команда забирает XML из `outbox\` по расписанию или вручную

## Формат входного JSON (ККЛ)

```json
{
  "kkl": [
    {
      "code": "24",
      "dpt": "7708",
      "date": "2026-03-24 01:30:00",
      "register": "12",
      "cashier": "697",
      "full": "1",
      "shift": "34",
      "lines": [
        {
          "receipt": "572",
          "product_code": "2891553",
          "qnt": "1",
          "price": "103",
          "sale": "70",
          "vat": "20",
          "oper": "01",
          "date": "2026-03-24 01:28:00"
        }
      ],
      "payments": [
        {
          "receipt": "572",
          "pay_type": "2",
          "sum": "70.00",
          "date": "2026-03-24 01:28:00"
        }
      ],
      "cards": [
        {
          "receipt": "572",
          "date": "2026-03-24 01:28:00",
          "card": "0001",
          "card_type": "0000001"
        }
      ]
    }
  ]
}
```

### Обязательные поля шапки ккл

| Поле | Описание |
|---|---|
| `code` | Номер ККЛ — уникальный идентификатор |
| `dpt` | Код подразделения (магазина). Используется как `SNDPRN` в IDoc — дополняется нулями до 10 символов |
| `date` | Дата и время. Форматы: `ГГГГ-ММ-ДД ЧЧ:ММ:СС` или `ДД/ММ/ГГГГ ЧЧ:ММ` |
| `register` | Номер кассового аппарата |
| `cashier` | Имя пользователя кассы (используется как код и ФИО кассира) |
| `full` | Признак: `0` — промежуточная ККЛ, `1` — итоговая (конец смены) |

## Формат выходного XML (WPUBON01)

Один файл на ККЛ. Один блок `<IDOC>` содержит все чеки из ккл.

```xml
<?xml version='1.0' encoding='utf-8'?>
<WPUBON01>
  <IDOC BEGIN="1">
    <EDI_DC40 SEGMENT="1">
      <DIRECT>2</DIRECT>
      <IDOCTYP>WPUBON01</IDOCTYP>
      <MESTYP>WPUBON</MESTYP>
      <SNDPOR>SAPVOG</SNDPOR>
      <SNDPRT>KU</SNDPRT>
      <SNDPRN>0000007708</SNDPRN>
      ...
    </EDI_DC40>
    <E1WPB01 SEGMENT="1">
      <KASSID>12</KASSID>
      <VORGDATUM>20260324</VORGDATUM>
      <VORGZEIT>012800</VORGZEIT>
      <BONNUMMER>572</BONNUMMER>
      <KASSIERER>697</KASSIERER>
      <CSHNAME>697</CSHNAME>
      <ZNOCARD>0001</ZNOCARD>
      <E1WPB02 SEGMENT="1">
        <QUALARTNR>EANN</QUALARTNR>
        <ARTNR>2891553</ARTNR>
        <VORZEICHEN>-</VORZEICHEN>
        <MENGE>1.000</MENGE>
        <E1WPB03 SEGMENT="1">
          <VORZEICHEN>-</VORZEICHEN>
          <KONDITION>VKP0</KONDITION>
          <KONDVALUE>70.00</KONDVALUE>
          <ZROUND>0.00000</ZROUND>
        </E1WPB03>
        <E1WPB04 SEGMENT="1">
          <MWSKZ>B2</MWSKZ>
          <MWSBT>11.67</MWSBT>
        </E1WPB04>
      </E1WPB02>
      <E1WPB06 SEGMENT="1">
        <ZAHLART>PTVI</ZAHLART>
        <SUMME>70.00</SUMME>
      </E1WPB06>
    </E1WPB01>
  </IDOC>
</WPUBON01>
```

### Именование выходных файлов

```
WPUBON01_{код_магазина}_{дата_YYYYMMDD}_{номер_кассы}_{номер_ккл}.xml
```

Пример: `WPUBON01_0000007708_20260324_12_24.xml`

## Таблицы преобразования кодов

### НДС (vat → MWSKZ)

| ККЛ `vat` | SAP `MWSKZ` | Ставка |
|---|---|---|
| `0` | `B0` | 0% |
| `10` | `B1` | 10% |
| `20` | `B2` | 20% |
| `22` | `E5` | 22% |
| любой другой | `??` | Неизвестный — WARNING в лог |

### Типы оплат (pay_type → ZAHLART)

| ККЛ `pay_type` | SAP `ZAHLART` | Описание |
|---|---|---|
| `1` | `PTCS` | Наличные |
| `2` | `PTVI` | Безналичные |
| любой другой | `????` | Неизвестный — WARNING в лог |

### Тип операции (oper → VORZEICHEN в E1WPB02)

| ККЛ `oper` | SAP `VORZEICHEN` | Описание |
|---|---|---|
| `01` | `-` | Продажа |
| `02` | `+` | Возврат |
| любой другой | `-` | Неизвестный — WARNING в лог |

> `VORZEICHEN` в `E1WPB03` (условие цены) всегда `-` независимо от типа операции.

### Квалификатор артикула (product_code → QUALARTNR)

| Диапазон `product_code` | SAP `QUALARTNR` | Описание |
|---|---|---|
| 100000–399999 | `ARTN` | Внутренний код товара |
| 500000–599999 | `ARTN` | Внутренний код товара |
| 700000–799999 | `ARTN` | Внутренний код товара |
| любой другой | `EANN` | Штрихкод (EAN) |

### Карты лояльности (cards[])

Все карты в массиве `cards[]` — карты лояльности (социальные, покупателей, сотрудников).
Первая карта чека передаётся в поле `ZNOCARD`. Банковских карт в `cards[]` нет — `KARTENNR` не заполняется.

### Расчётные поля

| Поле SAP | Формула | Примечание |
|---|---|---|
| `SNDPRN` | `dpt` + ведущие нули до 10 символов | `7708` -> `0000007708` |
| `VORGDATUM` | Дата из `lines[].date` -> `YYYYMMDD` | Берётся из первой строки чека |
| `VORGZEIT` | Время из `lines[].date` -> `HHMMSS` | |
| `KONDVALUE` | `sale × qnt`, округлить до 2 знаков | Сумма позиции |
| `MWSBT` | `sale × qnt × vat / (100 + vat)`, округлить до 2 знаков | Сумма НДС в цене |
| `ZROUND` | `(sale×qnt) − ROUND(sale×qnt, 2)` | Точное значение минус округлённое, 5 знаков |
| `CREDAT` | Текущая дата запуска конвертера -> `YYYYMMDD` | Системная дата |
| `CRETIM` | Текущее время запуска конвертера -> `HHMMSS` | Системное время |

## Мониторинг

### Лог файл

Открыть `logs\json_to_sap.log` — там полная история запусков:

```
2026-03-24 01:30:05 [INFO] === Конвертер ККЛ JSON -> IDoc WPUBON01 SAP запущен ===
2026-03-24 01:30:05 [INFO] Найдено файлов для обработки: 1
2026-03-24 01:30:05 [INFO] Обработка: kkl_20260324_12.json
2026-03-24 01:30:05 [INFO] Создан: WPUBON01_0000007708_20260324_12_24.xml (5 чеков)
2026-03-24 01:30:05 [INFO] OK: kkl_20260324_12.json -> WPUBON01_0000007708_20260324_12_24.xml (5 чеков)
2026-03-24 01:30:05 [INFO] === Готово ===
```

Уровни сообщений:
- `INFO` — штатная работа
- `WARNING` — некритичная проблема (неизвестный код НДС, код оплаты, пустые lines[])
- `ERROR` — файл не обработан, нужно разобраться

### Журнал SQLite (journal.db)

Открыть через любой просмотрщик SQLite (например [DB Browser for SQLite](https://sqlitebrowser.org/)) или через командную строку:

```
python -c "import sqlite3; [print(r) for r in sqlite3.connect('journal.db').execute('SELECT processed_at, kkl_filename, kkl_code, receipts_count, status FROM journal ORDER BY id DESC LIMIT 20')]"
```

Поля журнала:

| Поле | Описание |
|---|---|
| `kkl_filename` | Имя входного JSON файла |
| `kkl_code` | Поле `code` из шапки ккл |
| `kkl_date` | Поле `date` из шапки ккл |
| `register` | Номер кассы |
| `full` | Признак итоговой ккл (`0`/`1`) |
| `receipts_count` | Количество чеков в ккл |
| `out_filename` | Имя созданного XML файла |
| `processed_at` | Дата и время обработки |
| `status` | `OK` / `WARNING` / `ERROR` / `SKIPPED` |
| `warnings` | Список предупреждений (если есть) |
| `error_message` | Текст ошибки если `status=ERROR` |

## Возможные ситуации

| Ситуация | Что происходит |
|---|---|
| Файл уже обрабатывался | Пропускается (`SKIPPED`), дубль не создаётся |
| Файл не является валидным JSON | Пропускается, статус `ERROR` в журнале |
| Отсутствует обязательное поле шапки ккл | Запись ккл пропускается, `WARNING` в журнале |
| Пустой массив `lines[]` (нет чеков) | Запись ккл пропускается, `WARNING` в журнале |
| Неизвестный код НДС (`vat`) | `MWSKZ='??'`, обработка продолжается, `WARNING` в лог |
| Неизвестный тип оплаты (`pay_type`) | `ZAHLART='????'`, обработка продолжается, `WARNING` в лог |
| Неизвестный код операции (`oper`) | `VORZEICHEN='-'`, обработка продолжается, `WARNING` в лог |
| Ошибка записи XML в outbox | Повторить 3 раза с паузой 30 сек, затем `WARNING` |
| Необработанное исключение | Файл не перемещается, статус `ERROR` в журнале |
